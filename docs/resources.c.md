# `resources.c`

Status: draft for user approval; version 0.0.7.

## Purpose and behavior

Contains generated GLib resource bytes and registration code for the embedded GTK interface. It depends on GIO/GLib and includes compiler-specific constructor/destructor support. `resources_get_resource` provides access to the generated resource; initialization and finalization hooks manage its registration lifecycle on supported toolchains.

## Source of truth and build integration

The editable inputs are [resources.xml](resources.xml.md) and [interface.ui](interface.ui.md). The current Makefile generates **`build/resources.c`** and compiles that file for each target. The root-level `resources.c` is a separate existing generated copy and is not used by those compilation rules. Its embedded window title contains version 0.0.6, while the current UI source contains 0.0.7.

Regenerate resources through the Makefile when inputs change. Do not manually edit generated byte arrays or platform registration boilerplate. Build-directory resource copies do not need separate documentation.

## SOLID development direction

Follow the [project SOLID guidelines](README.md#development-direction-solid). Keep this artifact limited to resource embedding. Application behavior belongs in maintained C modules, while visual declarations belong in the UI source. Generated registration internals are not application extension points.
